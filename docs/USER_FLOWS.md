# Tab V1 user flows

## Create
Create Tab → choose name/category → choose equal or percentage split → creator becomes active → generate one invite code embedded in share link.

## Join
Open link or enter code → preserve invite through auth → preview → request join → every current active member approves → membership begins. Earlier expenses never include the new member automatically.

## Spend
Only the payer records their own payment → original currency and paid time → category → beneficiaries → historical USD value locked → ledger version increments. No Tab, no expense.

## Leave the night early
Request inactive → every other active member approves → inactive timestamp closes participation window. Prior expenses remain. New expenses exclude inactive member by default.

## Close
Any active member requests close → each member reviews relevant expenses → dispute if needed → unanimous approval of the current ledger version → any ledger mutation resets close approvals → lock → calculate minimal net transfers → settlement.

## Settlement copy
A final transfer is part of settling the group's combined Tab. It does not imply the sender originally owed that recipient.
